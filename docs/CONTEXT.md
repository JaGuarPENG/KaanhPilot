# KaanhPilot 机器人服务场景

本项目面向服务机器人接收业务请求、执行物理操作并交付结果的场景。本文只统一项目语言，不描述代码结构或实现方案。

## 业务请求

**订单（Order）**:
用户希望机器人完成的一次业务目标，例如取送一件商品或制作并运送一杯咖啡。
_Avoid_: 用“任务”同时表示用户需求和机器人执行记录

**机器人任务（Robot Task）**:
系统为执行一个订单而创建的、可排队并可追踪状态的执行单元；一个订单未来可以产生一个或多个机器人任务。
_Avoid_: 线程、请求

**任务链（Task Chain）**:
同一订单下具有固定先后依赖的一组机器人任务；前序任务未成功时，后序任务不能执行。
_Avoid_: 第二个任务队列、可任意插队的任务集合

**工作流请求（Workflow Request）**:
由前端、未来的语音交互或其他入口提交的结构化能力请求，包含工作流名称、参数、来源和幂等标识。
_Avoid_: LLM 动作、任意函数调用

## 机器人能力

**工作流（Workflow）**:
为了实现一个完整业务结果而编排的一组受控机器人能力，例如商品取送或咖啡制作。
_Avoid_: 脚本、Command 列表

**指令（Command）**:
对机器人、夹爪、相机或移动底盘执行的一次边界明确的底层操作。
_Avoid_: Workflow、Task

**Agent**:
能够根据目标选择或规划工作流的决策者；其输出仍需经过确定性的权限、安全与执行约束。
_Avoid_: 直接控制底层运动的 LLM

## 场景与感知

**咖啡工作站（Coffee Station）**:
由咖啡机、杯具、托盘、按键和相关视觉参照物共同构成的被机器人操作场景；咖啡机本身不提供网络控制接口。
_Avoid_: 咖啡机服务、咖啡机后端

**场景基准（Scene Reference）**:
用于确定工作站相对机器人坐标系位置和姿态的稳定视觉参照。
_Avoid_: 单个目标点

**操作目标（Manipulation Target）**:
机器人需要抓取、放置或接触的目标，其描述可包含位置、姿态、表面法向、置信度和视觉来源。
_Avoid_: 所有场景一律称为抓取点

**RGB-D 观测（RGB-D Observation）**:
同一时刻、像素对齐的彩色图像、深度图和有组织点云及其标定信息。
_Avoid_: 相机帧（未说明包含的数据时）
